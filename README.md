# مشروع الفهرسة النصية للغة العربية في PostgreSQL 16

---

## الأدوات المستخدمة في المشروع

* **قاعدة البيانات:** PostgreSQL 16
* **بيئة التشغيل والحاويات:** Docker و Docker Compose
* **لغة البرمجة:** Python 3.12 (مكتبات psycopg, pytest, pandas, fastapi)
* **إضافات قاعدة البيانات:** pg_trgm (للمقاطع الثلاثية) و unaccent
* **مجموعة البيانات (Dataset):** 100,000 مقال باللغة العربية (حوالي 49 مليون كلمة)

---

## فكرة المشروع والمشكلة

تفشل محركات وقواعد البيانات التقليدية في مطابقة النصوص العربية بدقة، نظراً لأن اللغة العربية لغة اشتقاقية صرفية غنية، حيث تتفرع من الجذر الواحد (مثل: كتب) مشتقات متعددة: (يكتبون، كاتب، كتاب، مكتبة).

إذا بحثت في PostgreSQL عبر التهيئة البسيطة (Simple) عن كلمة "كتب":
```sql
SELECT to_tsvector('simple', 'يكتبون في المكتبة') @@ to_tsquery('simple', 'كتب');
```
تكون النتيجة FALSE، لأن البحث يطابق الرسم السطحي للحروف فقط دون إدراك الرابط الصرفي بين المشتقات.

في هذا المشروع، تم تطبيق ومقارنة 6 طرق مختلفة للفهرسة واسترجاع المعلومات لتقييم الدقة وسرعة الاستعلام ومساحة التخزين.

```mermaid
flowchart TD
    A["100,000 مقال عربي"] --> B["تنظيف وتوحيد النص (normalize.py)"]
    B --> C["تخزين البيانات في PostgreSQL 16"]
    C --> D["تطبيق 6 طرق فهرسة (S0 إلى S5)"]
    D --> E["بناء فهارس GIN"]
    E --> F["تقييم 20 استعلام لغوي وقياس الدقة"]
```

## الطرق الـ 6 المقارنة

| الرمز | الطريقة | الوصف | مثال لكلمة «المكتبات» | حجم الفهرس |
|:---:|:---|:---|:---:|:---:|
| **S0** | البحث السطحي المباشر (Surface Simple) | يأخذ الكلمة كما هي دون أي تعديل صرفي | `المكتبات` | 255 MB |
| **S1** | البحث السطحي مع حذف كلمات التوقف | يستبعد حروف الجر والضمائر والروابط الشائعة | `المكتبات` | 178 MB |
| **S2** | قص الزوائد الصرفية (Light Stemming) | يحذف السوابق واللواحق الشائعة (الـ، والـ، ـات، ـون) مع الحفاظ على بنية الكلمة | `مكتب` | 143 MB |
| **S3** | استخراج الجذر الصرفي بالقوالب والأوزان | يستخرج الجذر الثلاثي عبر موازنة الكلمة بأوزان وقوالب الصرف العربي | `كتب` | 97 MB |
| **S4** | استخراج الجذر المعجمي (Dictionary Root) | يستخرج الجذر ويتحقق من صحته بمطابقته مع معجم الجذور المعتمد | `كتب` | 96 MB |
| **S5** | المقاطع الثلاثية للأحرف (Trigram) | يجزئ الكلمات إلى ثلاثيات حروف متداخلة لحساب نسبة التشابه الإملائي | `الم`، `لمك`، `مكت` | 207 MB |

## تنظيف وتوحيد النصوص (Normalization)

قبل إجراء الفهرسة، تُعالج النصوص عبر مسار التوحيد (`normalize.py`):
1. إزالة التشكيل، التنوين، وحركات الإعراب.
2. حذف المد والتطويل (الكشيدة).
3. توحيد صور الألف (أ، إ، آ -> ا)، والياء (ى -> ي)، والتاء المربوطة (ة -> ه).
4. تحويل الأرقام المشرقية إلى الأرقام القياسية (1, 2, 3).
* جميع عمليات التوحيد مدعومة باختبارات آلية تغطي كافة الحالات بنسبة نجاح 100%.

## نتائج التقييم

تم قياس أداء الأنظمة عبر 20 استعلاماً لغوياً نموذجياً يغطي مختلف الأنماط الصرفية:

| النظام | دقة أول 10 نتائج (P@10) | الاسترجاع الكلي (Recall) | حجم الفهرس | متوسط زمن الاستعلام |
|:---|:---:|:---:|:---:|:---:|
| **S0 (البحث السطحي)** | 35% | 44% | 255 MB | 127 ms |
| **S1 (مع حذف كلمات التوقف)** | 26% | 38% | 178 MB | 120 ms |
| **S2 (قص الزوائد الصرفية)** | **46%** (الأعلى دقة) | 67% | 143 MB | 218 ms |
| **S3 (الجذر الصرفي بالأوزان)** | 44% | **70%** | 97 MB | 387 ms |
| **S4 (الجذر المعجمي بالقاموس)** | 45% | **70%** (الأعلى استرجاعاً) | **96 MB** (توفير 62%) | 332 ms |
| **S5 (المقاطع الثلاثية Trigram)** | 5% | 11% | 207 MB | 64 ثانية |

## تحليل التداخل الدلالي (Over-stemming)

تتميز طرق التجذير الكامل (S3 وS4) بتقليص مساحة التخزين وزيادة معدل الاسترجاع، لكنها قد تواجه ظاهرة التداخل الدلالي عند رد كلمات مختلفة المعنى إلى نفس الجذر المشترك:
* **استعلام «بحر»:** استرجعت أنظمة الجذور وثائق تخص «البحرين» نظراً للاشتراك في الجذر (بحر)، بينما اقتصر نظام قص الزوائد (S2) على السياقات البحرية المباشرة.
* **استعلام «عين»:** جمعت أنظمة الجذور بين عين الماء وعين الإنسان والأسماء الجغرافية المشتقة.
* **ميزة أنظمة الجذور:** التفوق في معالجة جموع التكسير المعقدة والمصادر القياسية؛ فكلمة «أشجار» لا يربطها نظام قص الزوائد بمفردها «شجرة»، في حين يجمعهما نظام الجذور تحت الجذر (شجر) بنجاح.

## الاستنتاجات والتوصيات

1. **للتطبيقات العملية وتصدر النتائج الدقيقة:** نظام قص الزوائد **(S2 - Light Stemming)** يقدم أفضل توازن عملي بدقة تصل إلى 46% في النتائج العشر الأولى.
2. **لترشيد استهلاك مساحات التخزين:** نظام الجذر المعجمي **(S4 - Dictionary Root)** يحقق أقصى كفاءة تخزينية باختزال 62% من حجم الفهرس مع نسبة استرجاع بلغت 70%.
3. **التوصية الهندسية:** اعتماد معمارية بحث هجينة (Hybrid Search)، تبدأ بالبحث السطحي وقص الزوائد، ثم تتوسع تدريجياً للاشتقاق الجذري عند انخفاض عدد النتائج المسترجعة.

## تشغيل المشروع

### المتطلبات:
* Docker و Docker Compose
* Python 3.12

### الخطوات:

1. تشغيل قاعدة البيانات:
```bash
docker compose up -d
```

2. تثبيت الحزم المطلوبة:
```bash
pip install -r requirements.txt
```

3. التحقق من الاتصال وتشغيل حزمة الاختبارات:
```bash
python -m src.db.verify_env
pytest tests/
```

4. تحميل البيانات وبناء الفهارس:
```bash
python -m src.corpus.ingest_docs
python -m src.indexing.build_indexes
```

5. تشغيل تقييم الأداء:
```bash
python -m src.benchmarks.evaluate_ir
python -m src.benchmarks.overstemming_analysis
```

## تشغيل واجهة الويب (Web UI)

المشروع مزود بواجهة ويب تفاعلية متكاملة باللغة العربية:
* **مقارنة متزامنة بين الأنظمة الـ 6 (S0–S5):** تنفيذ الاستعلام بالتوازي وعرض النتائج جنباً إلى جنب مع إبراز الكلمات والمشتقات المستخرجة وزمن المعالجة بالملي ثانية.
* **التمثيل الصرفي التلقائي:** عرض صيغ الاستعلام المتحولة عبر مستويات المعالجة المختلفة فورياً.
* **الاستعلامات الذهبية النموذجية:** إمكانية تجربة 20 استعلاماً لغوياً متنوعاً بضغطة زر واحدة.

### التشغيل عبر Docker Compose:
```bash
docker compose up -d
```
ثم فتح المتصفح على: **`http://localhost:8000`** أو عبر النطاق المحلي: **`http://arabic-ir-web.arabic-ir.orb.local`**

### أو التشغيل المحلي المباشر:
```bash
uvicorn src.web.app:app --host 0.0.0.0 --port 8000 --reload
```
